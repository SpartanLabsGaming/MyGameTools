The plumbing every 2D multiplayer game needs — already written.

GameTools is a batteries-included engine layer: a composable game-object hierarchy, a stat system with proper buff stacking, pluggable spatial indexing, a typed event bus, a tiled map and zone model, and a UDP GameServer that speaks a typed command protocol. Spend your time on gameplay instead of infrastructure.

What you get

Each layer adds exactly one concern, so you can take the parts you want and leave the rest.

🕹️Composable game objects

GameObject → VisibleObject → Actor → Alive — position, rendering, movement, combat. Movement is a pluggable Movement strategy: chase-and-stop, chase-and-keep-chasing, fixed heading, or homing.

📊Stats that stack correctly

ModularStat reshapes a Double through any number of named StatMods; CombinedStat keeps a current/max pair in proportion when the ceiling moves, so a max-health buff never wastes or destroys the current value.

🗺️Pluggable spatial index

A SpatialIndex<E> port with two implementations — a point-region Quadtree (the default, via QuadtreeSpatialIndex) and a UniformGrid with O(1) amortised updates for roughly uniform density.

📡Typed event bus

World.events publishes EntitySpawned, AttackLanded, DamageDealt, EntityDied and more. Synchronous, in-order, single-threaded, with per-listener fault isolation.

🎯Standing orders

Actor.intent tracks what a unit was told to do while movement tracks how. issue(Intent) always tears the previous order down first, so orders are mutually exclusive by construction.

🎲Deterministic simulation

Every random choice goes through a seeded RandomSource, so a fixed seed and a fixed input sequence reproduce a run exactly. SimulationLoop adds an opt-in fixed-timestep driver with bounded catch-up.

🧭Maps, space and zones

TiledMap implements the Space port — terrain grid, static AABB geometry, named spawn points, loaded from a @Serializable JSON MapDefinition. ZoneGrid/ZoneIndex partition it and report every crossing.

🌐UDP server & command protocol

GameServer handles handshakes, one shared multiplexed socket and JSON broadcast; ClientCommand carries MoveTo, Follow, Attack and your own commands over a COMMAND <json> envelope, addressing objects by EntityId.

Architecture

Four inheritance layers, each one concern deep — plus the systems that own and observe them.

Responsibility of each layer
LayerResponsibility
GameObjectPosition, the active flag, and the tick() lifecycle hook every entity shares.
VisibleObjectRendering: area, colour, texture, angle and nested sub-objects (health bars, nameplates).
ActorMovement via a pluggable Movement strategy, and the standing order in intent.
AliveCombat: health, damage, attack timing/range/speed, evasion, faction and Player ownership.
ProjectileTravel-and-hit entities — home in on one target, or pierce in a straight line.
WorldOwns every object, reconciles the spatial index and the EntityId index each frame, drives the tick, publishes events.
EventBusSynchronous, single-threaded publish/subscribe, delivered in order with per-listener fault isolation.
SimulationLoopOpt-in fixed-timestep driver — a daemon thread calling tick() at a live-tunable rate.
GameServerUDP transport: handshakes, one shared multiplexed socket, input decoding, JSON broadcast.

Modules

Depend on the umbrella for everything, or on gametools-core alone when you don't need the server.

core

io.github.spartanlabsgaming:gametools-core

The object hierarchy, stats and buffs, SpatialIndex, Quadtree, UniformGrid, Space, EntityId, World, EventBus, SimulationLoop and the @Serializable geometry DTOs.

Depends on — nothing

net

io.github.spartanlabsgaming:gametools-net

GameServer, the MouseAction wire type, and the typed ClientCommand protocol under .command.*.

Depends on gametools-core

world Phase 1

io.github.spartanlabsgaming:gametools-world

TiledMap, TerrainLayer, StaticGeometry, SpawnPoint and the MapDefinition/MapLoader JSON format; Zone, ZoneGrid, ZoneIndex. Physics and vision are still to come.

Depends on gametools-core

umbrella start here

io.github.spartanlabsgaming:gametools

No source of its own — re-exports every module with api, so one dependency line pulls the whole framework, exactly as the pre-4.0.0 GameTools artifact did.

Depends on core · net · world

Sources & docs

The umbrella's -sources.jar and -javadoc.jar bundle the Kotlin sources and combined Dokka docs of every module, so IDE “Go to declaration” and quick-doc resolve through the single coordinate.

Upgrading from 3.x?

The single io.github.spartanlabsgaming:GameTools artifact became …:gametools (lowercase) in 4.0.0. Swap the one dependency line — the umbrella's transitive contents are unchanged, so no imports move.

Transitive dependencies

GameTools brings in Spartan Laboratories' WebTools and GeneralTools, plus kotlinx-serialization-json and the slf4j API — bring your own slf4j binding to see log output.

Testing & building

Five test levels, each independently runnable so CI can gate them separately. Every module carries its own five-level tree; each task fans out across all modules.

Gradle taskLevelScope
componentTest2 — ComponentIsolated component / business-logic tests
integrationTest3 — IntegrationIntegration & external interfaces (binds real UDP ports)
deterministicTest4a — DeterministicPure-logic input/output and law-based tests
e2eTest4b — End-to-endFull client↔server round trips (binds real UDP ports)
nonfunctionalTest4c — Non-functionalScalability & robustness (binds real UDP ports)

Because a GameServer binds a fixed common UDP port, any test task that starts one acquires a shared, single-permit Gradle build service, so port-binding tasks never run concurrently.
